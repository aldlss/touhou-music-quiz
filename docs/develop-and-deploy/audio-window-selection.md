# 随机音频窗口选择

## 问题

答题页面原本只随机选择一段音频。短题如果完全落在曲首、曲尾或较长停顿中，可能几乎听不到可用于辨认曲目的内容。

检测的目的不是排除所有停顿。短促留白可能属于正常编曲，长题中包含一小段停顿也不妨碍辨认。当前规则只在静音已经明显影响题目时换一个随机位置。

## 取片数量

设题目时长为 `D`，一次尝试需要的连续切片数为：

```text
B = ceil(D / 0.99)
```

源切片名义上为 1 秒，单独解码后通常略短。按 0.99 秒计算，可以避免合并后的音频不足目标时长。

曲目切片数少于 `B` 时，获取全部切片并从头播放。此时不存在完整的目标窗口，因此不进行静音检测。

## 静音检测

每次尝试先随机选择一个合法切片起点，获取并合并完整候选，再在候选余量内随机确定实际播放起点。检测只覆盖真正会播放的 `D` 秒。

PCM 按 20ms 分帧，静音阈值为 `-55dBFS`。每个声道分别计算能量，只要任一声道超过阈值，该帧就视为有声，避免双声道反相信号抵消。

设：

- `S`：播放窗口内的总静音时长；
- `L`：最长连续静音时长；
- `D`：播放时长。

两个限制分别为：

```text
总静音限制 = 0.6D
连续静音限制 = min(0.5D, 1s)
```

风险值为：

```text
risk = max(S / (0.6D), L / min(0.5D, 1s))
```

`risk < 1` 时直接使用；`risk >= 1` 时重新随机。静音段数量不单独计分：多个短停顿更可能是节奏或编曲选择，只有其总时长超过限制时才触发重试。

| 播放时长 | 总静音限制 | 连续静音限制 |
| ---: | ---: | ---: |
| 0.5s | 0.3s | 0.25s |
| 1s | 0.6s | 0.5s |
| 5s | 3s | 1s |
| 10s | 6s | 1s |

## 执行流程

1. 随机选择一个合法的连续切片范围。
2. 获取、解码并合并完整候选。
3. 在候选余量内随机确定实际播放起点。
4. 扫描实际播放窗口并计算 `risk`。
5. `risk < 1` 时立即返回，否则继续尝试，最多五次。
6. 五次都触发阈值时，返回 `risk` 最低的一次。

重试时从尚未使用的切片起点中等概率抽取；所有起点都使用过后，允许重复抽取。不同候选范围仍可重叠，已解码的切片会复用。

阈值是重试条件，不是播放合法性判断。因此算法不会因为整首曲目本身留白较多而报错，也不会无限重试。

## 成本

正常情况下只请求原本需要的 `B` 个切片，并增加一次线性 PCM 扫描。扫描过程中超过能量阈值便停止累加，正常有声帧通常不需要遍历整帧的所有样本。

只有检测到明显静音时才会增加尝试。不计解码回退时的重新请求，最坏请求量为 `5B`；不同尝试覆盖相同切片时会复用已经解码的结果。每次尝试的本地计算量为 `O(D)`，不扫描整首曲目。

浏览器原生解码失败时重新获取对应切片，再回退到 OGG Opus Worker；正常路径不会为了回退复制音频数据。同一个 Worker 的解码任务串行执行，页面离开时通过 `AbortSignal` 取消请求并停止后续步骤。

## 代码位置

- `app/_tools/audioWindowSelection.client.ts`：随机尝试、加载、解码、静音分析和最终选择。
- `app/_page/runningPage.tsx`：题目队列、音频上下文和 Worker 生命周期。
- `app/audio-window-test`：开发环境中的完整尝试试听页。
- `app/types.ts`：`Quiz.startTime` 数据契约。

实现使用独立函数，不使用 class。缓存和中间结果只属于当前一道题，选段结束后即可释放。

## 调整参数

当前的 `0.6`、`0.5` 和 `1s` 是根据现有曲库分布选择的初始值，不代表经过人工听感标注的最优参数。调试页会展示每次完整窗口、检测时间线和风险值；后续调整时应重点试听接近 `risk = 1` 的样本。
